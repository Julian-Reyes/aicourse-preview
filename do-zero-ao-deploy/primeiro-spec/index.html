Do Zero ao Deploy · Módulo 3 · Aula 3.1

3.1 Seu primeiro SPEC.md

Aprenda a escrever um spec, a lista curta que faz a IA construir o que você quer (e não o que ela imagina).

⏱ 15 min

O problema: pedidos vagos

Peça “faz um app de lista de compras” para uma IA e ela vai ter que adivinhar um monte de coisa. Tem login? Salva onde? Usa React? Funciona no celular?

Ela adivinha, e muitas vezes exagera: você recebe um projeto enorme, cheio de coisas que não pediu e não entende.

Um spec resolve isso. É um arquivo curto, chamado SPEC.md, onde você decide antes o que quer e o que não quer. A IA segue o spec, e você consegue conferir se ela seguiu.

Pedido vago Com spec
A IA decide o tamanho do projeto Você decide o tamanho do projeto
Aparecem funcionalidades que você não pediu A seção “fora do escopo” impede isso
Difícil saber se ficou pronto Você tem uma lista de “pronto quando” para conferir
Tudo de uma vez Um passo de cada vez, testando no caminho

As partes de um bom spec

Seção Para que serve
Objetivo O que o app faz, em uma ou duas frases
Para quem Quem usa e onde (celular, computador)
Funcionalidades essenciais O mínimo para o app ser útil, uma por linha
Extras O que pode esperar até o essencial funcionar
Fora do escopo O que a IA não deve fazer
Tecnologia Com o que construir. Simples é melhor no começo.
Pronto quando Como você vai saber que funcionou
Como trabalhar Regras para a IA: um passo por vez, explicar o que mudou
💡
A seção mais subestimada

“Fora do escopo” parece inútil, mas é a que mais economiza tempo. Escrever “sem login, sem banco de dados” evita que a IA monte uma estrutura gigante para um app que cabe num arquivo.

Uma boa funcionalidade é específica e testável. Compare:

  • Ruim: “deixar o app bonito”
  • Bom: “os botões têm pelo menos 44px de altura, para dar para tocar no celular”

Monte o seu

Preencha os campos e veja o SPEC.md se formando ao lado. Sem ideia? Clique em Ver um exemplo pronto. O que você digita fica salvo neste navegador.

Monte seu spec

Gerador de SPEC.md

SPEC.md
# SPEC: (nome do projeto)

## Objetivo
(preencher)

## Para quem
(preencher)

## Funcionalidades essenciais
- (preencher)

## Extras (só depois do essencial funcionar)
- (preencher)

## Fora do escopo (não fazer)
- (preencher)

## Tecnologia
HTML, CSS e JavaScript puro (sem framework)

## Pronto quando
- (preencher)

## Como trabalhar
- Implemente uma funcionalidade essencial de cada vez.
- Depois de cada passo, pare e me explique o que mudou antes de continuar.
- Use código simples e comentado; estou aprendendo.

Usando o spec com o Claude Code

  1. Clique em Baixar e mova o SPEC.md para a pasta do projeto (pode ser uma pasta nova, como a meu-primeiro-app).
  2. Abra o Claude Code nessa pasta (claude) e peça um plano antes de qualquer código:
Leia o SPEC.md. Antes de escrever código, me diga em poucas linhas como você pretende fazer e quais arquivos vai criar.
  1. Se o plano fizer sentido, peça só o primeiro passo:
Ótimo. Implemente só a primeira funcionalidade essencial e pare para eu testar.
  1. Teste no navegador. Funcionou? Peça a próxima. Não funcionou? Descreva o que aconteceu (“cliquei em adicionar e nada apareceu”) e peça para ele corrigir.
💡
Mudou de ideia? Mude o spec

Se você decidir mudar alguma coisa no meio do caminho, atualize o SPEC.md primeiro e avise o Claude: “atualizei o SPEC.md, leia de novo”. Assim o spec continua sendo a fonte da verdade, e não uma conversa longa que ninguém lembra.
