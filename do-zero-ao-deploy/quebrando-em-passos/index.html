Quebrando o projeto em passos

Por que pedidos grandes dão errado, e como dividir qualquer app em passos pequenos que você consegue testar.

⏱ 15 min

O problema dos pedidos gigantes

“Faça o app inteiro” quase sempre termina igual: centenas de linhas de uma vez, alguma coisa quebrada no meio, e você sem saber onde. Quanto maior o pedido, mais difícil é achar o erro.

A solução é simples: passos pequenos, cada um testável.

A regra de ouro

Todo passo termina com algo que você consegue ver funcionando no navegador. Se você não consegue testar, o passo ainda está grande demais (ou abstrato demais).

Uma funcionalidade inteira de cada vez

Um erro comum é dividir por “camadas”: primeiro todo o HTML, depois todo o CSS, depois todo o JavaScript. Assim, nada funciona até o final.

O jeito certo é fazer uma funcionalidade completa de cada vez: o botão de adicionar, com o HTML, o estilo e o código dele. Testou, funcionou? Próxima.

Coloque em ordem

Os passos da lista de compras, na ordem

  1. 1Publicar no GitHub Pages
  2. 2Página com título e uma lista fixa de exemplo
  3. 3Ajustar o visual para o celular
  4. 4Campo e botão que adicionam um item à lista
  5. 5Salvar a lista no navegador para não sumir ao recarregar
  6. 6Clicar num item marca como comprado (riscado)
  7. 7Botão para apagar um item

Bom passo ou grande demais?

Separe
  • Criar o app inteiro
  • Adicionar um campo e um botão que coloca o texto na lista
  • Fazer o servidor, o login e o banco de dados
  • Salvar a lista no navegador para não sumir ao recarregar
  • Deixar tudo bonito e profissional
  • Mostrar "Nenhum item ainda" quando a lista estiver vazia

Coloque os passos no spec

Acrescente uma seção Passos no seu SPEC.md. Se não souber por onde começar, peça ajuda ao próprio Claude:

Leia o SPEC.md e proponha uma lista de passos pequenos para construir o app. Cada passo deve terminar com algo que eu consiga testar no navegador. Não escreva código ainda.

Revise a lista: corte o que for grande demais, junte o que for pequeno demais. Depois, trabalhe assim:

Implemente o passo 1 do SPEC.md e pare para eu testar.
💡
Salve uma versão a cada passo

Quando um passo funcionar, salve uma versão do projeto (um “commit”, que você viu na aula do GitHub Pages e aprofunda no módulo 6). Se o próximo passo der errado, você volta para a última versão boa em segundos.
