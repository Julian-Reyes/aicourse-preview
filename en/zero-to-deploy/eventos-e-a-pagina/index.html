2.5 Events and the page, making clicks do things

How JavaScript finds an element on the page, changes its text, and reacts to clicks and to what the person types.

⏱ 25 min

The page is made of elements

So far the code has only talked to the console. In a real app, it changes the page: it swaps a piece of text, shows a number, paints the background. The page is made of elements written in HTML, like <h1> (a heading), <p> (a paragraph), and <button> (a button).

For JavaScript to change an element, it first has to find it. The most common way is to give the element an id (a unique name) in the HTML and look it up with document.getElementById:

addEventListener: “when this happens, do that”

A page that changes by itself isn’t much use. What matters is reacting to what the person does: a click, a key, some typed text. Each of these is an event. And addEventListener says: when this event happens on this element, run this function.

“Hello, world!” again

Remember the button that changes the background color, from the first module? Now you can read every line of it:

Try it

Hello, world!

Result
  • const colors = [...] is a list of colors.
  • let index = 0 is a variable that changes: it keeps the position of the current color.
  • addEventListener('click', () => { ... }) is an event that runs a function on every click.
  • index = (index + 1) % colors.length adds 1, and % (the remainder of a division) brings it back to 0 after the last color.
  • document.body.style.background = colors[index] takes the color at that position and paints the background.

Challenges:

  1. Add a new color to the list, for example '#c7d2fe'. Nothing else needs to change, because the code uses colors.length.
  2. Make the heading change too. In the HTML, give the heading an id: <h1 id="title">. In the JavaScript, inside the click, change its textContent to `Color ${index + 1} of ${colors.length}`.

The button that does nothing

This is the bug you’ll run into most at the start: you click, and nothing happens.

Find the bug

Clicking the button does nothing, and the console shows “Cannot read properties of null (reading 'addEventListener')”. Which line has the problem?

Click the line with the problem.

Where you’ll see this in the course

  • In the 3D game, the keydown and keyup events say when a key was pressed and released. The game keeps track of it in an object, keys[e.code] = true, and on every frame checks which arrows are held down. On a phone, the on-screen buttons use the pointerdown event to do the same.
  • In the map app, the check-in buttons live inside the map’s popups. Instead of putting an event on each button, the app listens to clicks on the whole page with document.addEventListener('click', ...) and checks which button was clicked.
  • In the AI app, the choose-photo field uses the change event (written as onchange), which happens when the person picks a file.
💡
When a button does nothing

Open the console (in the browser, F12 or right-click → Inspect → Console) and look for an error in red. Copy the error and send it to the AI with the context: “This button does nothing when I click it. The console shows this error: [paste it here]. Find the cause before changing anything.”
