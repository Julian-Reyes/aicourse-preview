2.2 Functions, the recipes of code

What a function is, how to pass data into it, what return does, and why the AI splits everything into functions.

⏱ 20 min

A function is a recipe

A function is a named piece of code you write once and use as many times as you want. Think of a recipe:

  • Ingredients: the data you pass in (the parameters).
  • Method: the code inside the braces { }.
  • The finished dish: what it gives back with return.

return: giving back isn’t showing

The most common beginner mistake: the function does the calculation but doesn’t give it back. Without return, the function ends and the result is lost. Whoever called it gets undefined (something like “there’s nothing here”).

Where you’ll see this in the course

  • In the 3D game, the function alturaEm(x, z) takes a point on the map and returns the ground height there. The whole terrain and the collision check use that same function.
  • In the map app, a function takes two positions and returns the distance between them, to sort the cafes from nearest to farthest.
  • In the “Hello, world!” button, the code that runs on every click is a function. You’ll see that in the lesson on events.
💡
Ask the AI for small functions

Good code is made of small functions, each with one job and a clear name. When a file gets confusing, ask: “Split this code into small functions, with names that say what each one does. Don’t change the behavior.” And when you don’t understand a function: “Explain this function in plain English: what it takes, what it does, and what it returns.”
