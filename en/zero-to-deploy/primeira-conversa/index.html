From Zero to Deploy · Module 1 · Lesson 1.4

Talking to Claude Code

How to ask, review, interrupt, and start over. The way of working you'll use in every project.

⏱ 15 min

A good request has four parts

  1. What: what you want to exist or change.
  2. Where: which file or part of the app.
  3. How you’ll know it works: what you’ll see when it’s right.
  4. Limits: what not to do.

Compare:

fix the button
In index.html, the "Add" button does nothing when I click it. I want it to add the text from the input to the list below and clear the input. Don't change how the page looks.

The second request has everything: what, where, how you’ll know it works, and a limit. The AI doesn’t have to guess.

Sort it

Vague or clear?

  • Make the app better
  • On phones, the title gets cut off. Make the title font smaller only on screens narrower than 500px.
  • Make it like Instagram
  • When the list is empty, show the text "No items yet" in its place.
  • There's an error, fix it

Ask for a plan before code

For anything bigger than a small change, ask for a plan first:

Before changing any files, explain in a few lines how you plan to do this.

Reading the plan takes 30 seconds and saves half an hour of code going in the wrong direction. Claude Code also has a plan mode, where it only plans and doesn’t edit anything. Press Shift+Tab to switch between modes.

Mention files by name

Claude Code reads project files when it needs to, but you can point it straight at one: type @ and the start of the file name (for example, @index.html) to include it in your request.

Reviewing what it does

Before editing, Claude Code shows you the change: removed lines in red, new lines in green. Read it before approving. If you don’t understand it, ask:

Before I approve: what does this change do and why is it needed?

When things go wrong

Situation What to do
It started doing something you didn’t want Press Esc to interrupt
The change turned out badly Ask: “undo the last change” (in module 7 you learn to go back to earlier versions with Git)
The conversation got long and confused Type /clear and start over, explaining the context in a few lines
You closed the terminal by accident Run claude -c in the same folder to pick up where you left off
💡
Short conversations, clear context

Very long conversations confuse the AI. When one topic is done, use /clear and start the next one fresh. In module 3 you’ll learn to keep important context in a file (CLAUDE.md), so you don’t have to repeat yourself.

  3. 3Ask for the next step
