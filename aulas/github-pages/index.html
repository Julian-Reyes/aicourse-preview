Do código ao ar: publicando no GitHub Pages

Coloque seu app na internet de graça, com um link para mandar para qualquer pessoa.

⏱ 20 min

O que você vai fazer nesta aula

Colocar o meu-primeiro-app no ar, de graça, com um link do tipo seu-usuario.github.io/meu-primeiro-app que abre em qualquer celular.

Três palavras para entender

  • Git guarda o histórico de versões do seu projeto, no seu computador. Cada versão salva se chama commit, como uma foto do projeto naquele momento.
  • GitHub é um site que guarda uma cópia do projeto na nuvem.
  • GitHub Pages é um serviço grátis do GitHub que transforma essa cópia num site público.

Antes de começar

  • Crie uma conta grátis em github.com se ainda não tiver.
  • Confira se o Git está instalado:
git --version

No Mac, se ele não estiver instalado, o sistema oferece para instalar as ferramentas de desenvolvedor: aceite. No Windows, instale o Git for Windows.

⚠️
Tudo no GitHub Pages é público

Qualquer pessoa pode ver os arquivos do seu site. Nunca coloque chaves de API, senhas ou dados pessoais neles. No módulo 5 do curso completo, você aprende o jeito seguro de usar chaves de API.

Passo 1: Salvar uma versão com Git

Abra o Claude Code na pasta do projeto e peça:

Inicie um repositório Git nesta pasta e faça o primeiro commit com todos os arquivos. Explique cada comando que você rodar.

Leia as explicações. Você não precisa decorar os comandos, mas precisa saber o que cada um faz.

Passo 2: Enviar para o GitHub

Escolha um dos dois caminhos.

Caminho A: pelo site do GitHub

  1. No GitHub, clique em New repository.
  2. Nome: meu-primeiro-app. Marque Public. Não adicione README.
  3. Clique em Create repository e copie o endereço que aparece (termina em .git).
  4. No Claude Code, peça:
Conecte este repositório ao GitHub em https://github.com/SEU-USUARIO/meu-primeiro-app.git e envie o código para a branch main.

Troque SEU-USUARIO pelo seu usuário do GitHub. Se pedir login e a senha não funcionar, é normal: o GitHub não aceita mais senha pelo terminal. Use o Caminho B, que resolve o login.

Caminho B: pelo GitHub CLI (mais rápido)

Instale o GitHub CLI, faça login uma vez e crie o repositório com um comando só:

gh auth login
gh repo create meu-primeiro-app --public --source=. --push

Passo 3: Ligar o GitHub Pages

  1. No repositório, no GitHub, abra Settings.
  2. No menu lateral, clique em Pages.
  3. Em Build and deployment, escolha Source: Deploy from a branch.
  4. Selecione a branch main e a pasta / (root). Clique em Save.
  5. Espere um ou dois minutos e recarregue a página. O link do seu site aparece no topo.
💡
A página inicial precisa se chamar index.html

O GitHub Pages procura um arquivo chamado exatamente index.html na raiz do projeto. Se o seu tiver outro nome, peça para o Claude renomear.

O bug clássico do primeiro deploy

Você testou com um servidor local e estava tudo lindo. Publicou, abriu o link e… o site aparece sem nenhum estilo, só texto preto no fundo branco. O problema está numa linha deste arquivo:

Ache o bug

Por que o CSS sumiu no GitHub Pages?

Clique na linha que tem o problema.

A IA comete esse erro com frequência. Se acontecer com você, já sabe o que pedir: “use caminhos relativos para os arquivos CSS e JS”.

Faça commit e push das mudanças com uma mensagem que descreva o que mudou.

Em um ou dois minutos, o site no ar se atualiza sozinho.
